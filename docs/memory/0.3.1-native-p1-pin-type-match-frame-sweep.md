# P1 pin — `checker::type_match` and `lir::frame_sweep_inst` facet classification

**Base:** `fix/retirement` @ `7a76fce6` (branch `p1/pin-type-match-frame-sweep`). 5 of ~8 native
by-address bugs fixed; this pin classifies the two the plan named as remaining, to decide the
GO/NO-GO on "DPS closes the native fixpoint."

**Question per blocker:** does the fault sit on the RETURN / TAIL-MERGE facet (an aggregate born
in a tail `match`/`if` arm and returned/merged, its per-instruction frame slot reclaimed before the
caller reads it — **DPS closes this by construction**) or on a PAYLOAD-BIND facet (a variant
payload bind / slice-element write / index-store — **DPS does NOT close it**, it needs a point-fix)?

## How it was reproduced (cheap, no full ladder)

`bootstrap/teko.c` on this commit is STALE (last touched `b4b83c33`, pre the recent native fixes);
a compiler `cc`-linked from it honest-stops on `slice element index-assignment not yet lowered`.
So the real compiler had to be rebuilt from the branch source, WITH the doubling that washes out
the stale seed's artifact:

| stage | how | result |
|---|---|---|
| gen0 | `cc` bootstrap/teko.c | ok (stale native backend) |
| gen1 | gen0 `TEKO_BACKEND=c` builds branch source | ok, but its native backend crashed EMITTING the 10 MB compiler object (`tk_slice_push_r`/`tk_region_alloc` under `backend::elf_partition_data_rel_ro`) — a STALE-gen0 miscompilation of the ELF emitter, not a source bug |
| gen1b | gen1 `TEKO_BACKEND=c` builds branch source (the `gen0_to_gen1` doubling) | ok — the current algorithm rendering itself |
| gen2 | gen1b `TEKO_BACKEND=native` builds the compiler | ok, exit 0, peak 3431 MB — the NATIVE-built compiler, the faulting binary |

gen2 is then run (under `setarch -R`, gdb) on ~5-function inputs. The crashes are in gen2's OWN
natively-compiled functions; the standalone-shape mirrors do NOT fault (the disease is integration:
corrupt data from an earlier native-lowered function reaches these sites), which is why gen2 is
required rather than a tiny standalone binary.

Repro inputs committed: `examples/probes/type_match_merge_dangle` (C3),
`examples/probes/native_isel_elem_box` (C2's live successor), `examples/probes/frame_sweep_merge`
(the faithful `frame_sweep_inst` mirror — it PASSES natively, which is itself evidence).

## C3 — `checker::type_match`: RETURN / TAIL-MERGE facet. DPS CLOSES IT. **GO.**

gen2 checking `type_match_merge_dangle` SIGSEGVs at **`teko_teko__checker__type_match+0xe85`**
(runtime `0x39f804`; +0xe85 is EXACTLY the offset the prior func-type note pinned), checker item 3,
on the variant `match`:

```
=> type_match+0xe85:  mov (%rax),%rcx        rax = 0x0   (NULL)
bt: type_match <- type_dispatch <- type_expr <- type_block <- type_function <- type_item
```

Disassembly of the fault window (the arm-type fold loop, typer.tks:3986-3993):

```
type_match+0xe25:  mov $0xf94,%r14 ; mov $0x1d,%r13     ; dead line/col consts (match gdb r14/r13)
        +0xe37:  r10 = [rsp+0x278]   (loop index j)
                 r11 = [rsp+0x240]   (arms.len)  ; cmp -> if j<len continue
        +0xe5b:  rax=8; rcx = j*8; r10 = [rsp+0x238] (arms.ptr); rax = arms.ptr + j*8
        +0xe85:  mov (%rax),%rcx     ; load arms[j]  <-- FAULT: arms.ptr = 0, j = 0
        +0xe88:  rax = *(arms[j] + 0x28) ; rcx = *(arms[j] + 0x30)  ; arms[j].body.ptr / .len (fat)
                 call teko_teko__checker__tblock_diverges(body.ptr, body.len)
```

The slice `arms` (base `[rsp+0x238]`, len `[rsp+0x240]`) has **len > 0 but ptr = NULL** — a corrupt
fat-slice header. It is stored to those slots straight out of the merge, at `type_match+0x570`:

```
+0x55b:  call teko_teko__checker__adopt_match_arm_literals
+0x57e:  store -> [rsp+0x238] (base)
+0x58c:  store -> [rsp+0x240] (len)
```

i.e. `arms = match match_join_anchor(typed) { Type as anchor => adopt_match_arm_literals(typed,
anchor); null => typed }` (typer.tks:3982). In `read`'s `match t { A as a => a.x; B as b => b.y }`
the arm leaves are field accesses (non-literal), so `match_join_anchor` returns a `Type` and the
merge takes the `adopt_match_arm_literals` arm. That callee builds `out: []TArm` by push and returns
it in tail position; conveyed through the match MERGE into `arms`, the fat header's **`.ptr` half
arrives NULL** (the merge block-arg for the pointer half defaulted — the same fat-through-merge
shape degrau 5 fixed for `match`-VALUE `str`, here for a returned `[]TArm`).

**Facet: RETURN / TAIL-MERGE.** The faulting value is an aggregate (`[]TArm`) produced in a tail
arm / callee return and conveyed through a `match` merge, its header not correctly copied into the
caller's `arms` destination. Destination-passing style — birthing `arms` in the caller's slot and
having both merge arms build directly into it — closes this by construction. **DPS closes C3.**

## C2 — `lir::frame_sweep_inst`: PAYLOAD-BIND facet (and already subsumed). DPS does NOT close it. **NO-GO.**

gen2 does **not** fault in `frame_sweep_inst`. On `in_nomatch` / `native_isel_elem_box` it walks
`frame_escape_window` (which runs `frame_sweep_inst` per item, unconditionally, NOT gated by
`--no-verify`) cleanly and crashes DEEPER. Disassembling gen2's own `frame_sweep_inst`/`frame_mark`
explains why, and answers the design map's open (a)/(b)/(c):

- **Every `FrameSet` return is BOXED.** `frame_sweep_inst` emits `tk_slice_elem_box(24)` before each
  `ret` (`+0x1c0`, `+0x23e`, `+0x3d8`), and so does `frame_mark` (both the `return set` path and the
  `FrameSet { marked = fs; grew = true }` tail). The return-side copy already materializes the
  aggregate past the frame — **candidate (a), "the `FrameSet` returned through the `return if` merge
  is a reused slot," is FALSE**: the return / tail-merge facet is handled here.
- **The residual hazard is the in-place `[]bool` write.** `frame_mark` lowers `mut fs = set.marked;
  fs[v to u64] = true` as `r15 = fs.ptr (= set.marked.ptr); mov $1,(r15 + v)` — an in-place
  index-store into the input's `[]bool` buffer (`frame_mark+0x2a0`). That is **candidate (b), the
  PAYLOAD-BIND / slice-element-write facet.** It happens to be benign on this commit because the
  buffer is root-allocated (`false_marks` -> `list::push` -> `tk_slice_push`/`tk_alloc` in the root
  region), so it outlives — which is why `frame_sweep_inst` no longer crashes at all.

So `frame_sweep_inst`'s only by-address facet is PAYLOAD-BIND, and it is currently subsumed. The
live native by-address crash that stands where it did is one lowering-stage deeper, and it is the
SAME family:

```
in_nomatch / native_isel_elem_box, gen2 native build:
=> tk_region_alloc+261:  mov 0x10(%rax),%rdx    rax = 0x5550037d4cc2  (region ptr, high bytes stomped)
bt: tk_region_alloc <- tk_alloc <- tk_slice_elem_box <- backend::select_fused_branch_x86
    <- select_branch_x86 <- select_inst_x86 <- ... <- build::emit_native_x86
```

`select_fused_branch_x86` boxes a 24-byte aggregate slice ELEMENT (`tk_slice_elem_box`, the
NATIVE-AGG-SLICE-BY-ADDRESS push-box of degrau 4) and finds the current-region pointer already
corrupt — a WILD WRITE from an earlier out-of-bounds element/index store stomped the arena
metadata. A second input (`in_frame`, with `let` bindings) faults in
`lir::binding_conveys_escape -> lir::contains_str -> tk_str_eq -> memcmp` on a corrupt `str.ptr`
(`rdi = 0xffff9900`) — a `[]str` (the escaping-vars list) whose element header is stomped. Both are
slice-element-write / wild-write symptoms, **PAYLOAD-BIND family, not return/tail-merge.**

**Facet: PAYLOAD-BIND.** DPS (which fixes birth-in-the-caller for returns/tail-merges) does NOT
close it. **NO-GO for C2.** Point-fix family: **region-bracket / self-append** — the #5
`push_inst_block` family (an aggregate slice-ELEMENT boxed/written in a region reclaimed under its
container). The fix brackets the element box to an outliving region / makes the current-region and
the escaping-`[]str` element writes park-safe, exactly as `74622f77`/`5026006a`/the #5 escape-name
fix did for their sites.

## Verdict

- **C3 `type_match` = RETURN / TAIL-MERGE facet → DPS closes it (GO).**
- **C2 `frame_sweep_inst` = PAYLOAD-BIND facet → DPS does NOT close it (NO-GO).** Its return facet
  is already boxed; its residual hazard is the in-place `[]bool` element-write, currently subsumed,
  and the live native by-address crash in its place (`select_fused_branch_x86` element-box against
  stomped region metadata; `contains_str` corrupt `[]str` element) is the slice-element-write /
  wild-write family.

**Overall: NOT both return-facet → NO-GO on "DPS alone closes the native fixpoint."** DPS should
still be built (per plan §11 it lands memory + correctness, and it closes `type_match` and the
return/tail-merge family). But the fixpoint track DECOUPLES: at least one payload-bind point-fix in
the **region-bracket / self-append** family is required for the element-box / wild-write crash that
is the live successor of `frame_sweep_inst`. Expect the func-type note's "1-3 behind" bugs to be of
this same payload-bind family; each is cheap-pinnable by this same gen2 + gdb + objdump method.
