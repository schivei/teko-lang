# native/iface-conformance: reproduced native miscompile of interface signature matching

## Symptom (gen2 native-built, rejects a VALID program the C route accepts)
```
src/io/stream.tks:209:10: 'NullStream' method 'close' does not match interface 'teko::io::Closer's signature
src/build/project.tks:1439883991:21845:
src/checker/escape.tks:1439883991:21845:
...
```
`NullStream.close(self) -> error | null` and `Closer.close(self) -> error | null` are IDENTICAL,
so `method_sig_matches` (src/checker/collect.tks:996) must return true. gen2 returns false.

## Garbage-line fingerprint = by-address corruption
Column `21845` = 0x5555 — the top bytes of a PIE/heap pointer (0x5555_5555_xxxx under setarch -R).
A `Position` (line/col) is being read from a slot that actually holds a POINTER: a value used in
the signature-matching path escaped into a region that was reclaimed, so its position/str fields
now read pointer bytes. Same family as 5026006a (bracket_to_root) and 74622f77 (name_escapes_body).

## Reproduction ladder (bootstrap/teko.c is a STALE seed lacking both prior fixes)
- gen0 = cc-link bootstrap/teko.c.
- gen0 --C--> gen1 (fixed codegen, but its OWN native body free-olds copy_relocs_to_current_region_x86
  because stale gen0 emitted tk_slice_push_fo there): gen1 SIGSEGVs native-building gen2.
- gen1 --C--> genB (clean native body: gen1's fixed codegen denies that free-old; verified
  tk_slice_push, not _fo, at copy_relocs).
- genB --native--> gen2 (clean, no crash, peak ~3.3 GB).
- gen2 --native--> gen3: REJECTS stream.tks:209 with the garbage-line fingerprint. <-- THE BUG.

CI reaches this same bug directly from the released seed (which HAS the two prior fixes), so its
gen1==my genB.
